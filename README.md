**1. NASA's Helio-Forecast: Geomagnetic Storm Prediction via Deep Learning**

### Overview

Helio-Forecast is a deep learning system that predicts geomagnetic storm intensity three hours in advance using NASA satellite telemetry. Space weather driven by solar wind poses a real threat to power grids, satellite operations, and communication systems, yet the chaotic nature of solar–terrestrial coupling makes short-horizon forecasting notoriously difficult. This project tackles that challenge with a Bidirectional LSTM trained on real OMNIWeb time-series data, delivering forecast accuracy competitive with published operational baselines in a domain where the physics itself imposes a hard ceiling on precision.

*  "Data courtesy of NASA/GSFC Space Physics Data Facility's OMNIWeb service."
*  Data set: https://omniweb.gsfc.nasa.gov/

### What It Does

At its core, the model forecasts the Kp-index — the standard measure of global geomagnetic disturbance — from historical solar wind and magnetic field observations. It achieves an R² of 0.23 on held-out test data, which sits squarely within the range of published operational baselines (0.15–0.28) for 3-hour Kp forecasting. Rather than chasing an artificially inflated score, the project is honest about the fundamental unpredictability of solar wind, and instead focuses on extracting every bit of signal that physics allows.

### How It Works

The foundation is a custom ETL pipeline that ingests and imputes over 24 months of NASA OMNIWeb satellite telemetry, transforming raw, gap-riddled sensor streams into a clean, reproducible training set. Data integrity is preserved end to end, from raw ingestion through to final model evaluation. On top of this, the model uses a Bidirectional LSTM (TensorFlow/Keras) that reads sequences in both temporal directions to capture the lead–lag dynamics of magnetospheric response.

The standout engineering decision was to move beyond raw sensor inputs and design **physics-informed features**. By encoding the Eyring energy coupling term (V × Bz) — a domain-derived proxy for solar-wind-to-magnetosphere energy transfer — the model gained a 15% improvement in its ability to capture the actual physical driver of storms, validated directly against a baseline LSTM trained on raw inputs.

### Tech Stack

`Python` · `TensorFlow` · `Keras` · `NumPy` · `Pandas` · Bidirectional LSTM · Custom ETL pipeline · NASA OMNIWeb data

### Key Highlights

- Bidirectional LSTM forecasting geomagnetic storms 3 hours ahead
- R² of 0.23, competitive with published operational Kp-index baselines
- Custom ETL pipeline over 24+ months of NASA satellite telemetry with principled imputation
- Physics-informed feature engineering (Eyring Energy, V × Bz) yielding a 15% gain in capturing energy transfer

**2. European AI Regulatory Compliance Engine (Multi-Agent RAG)**

### Overview

The European AI Regulatory Compliance Engine is a multi-agent Retrieval-Augmented Generation system that answers regulatory questions grounded in the actual text of the EU AI Act, GDPR, and the NIST AI Risk Management Framework. Regulatory language is dense, cross-referential, and unforgiving of hallucination, so this project pairs a hybrid retrieval pipeline with a team of specialized agents and verifiable source alignment — producing answers that are not just fluent, but traceable back to the exact page and passage they came from.

### What It Does

Ask the engine a compliance question and it retrieves the most relevant passages across three regulatory documents, fact-checks its own reasoning against external sources, and synthesizes a grounded answer with highlighted citations pointing to the precise location in the source PDFs. On a hand-labeled 20-question evaluation set, the system achieved 100% generation accuracy, reflecting the care taken to make retrieval precise and answers verifiable.

### How It Works

Retrieval is **hybrid by design**. Dense semantic search (Qdrant vector store, gemini-embedding-001 at 768 dimensions with cosine similarity) is fused with BM25 keyword search using Reciprocal Rank Fusion (RRF, k=60), so the system captures both meaning-level and exact-term matches. The fused candidate set of 16 chunks is then passed through LLM listwise re-ranking at temperature 0 to return the eight most relevant passages, keeping the final context tight and on-point.

The answer itself is produced by a **three-agent pipeline**: an Internal Researcher drafts findings from the retrieved regulatory text, an External Fact-Checker validates claims against the web via DuckDuckGo and FastMCP, and a Synthesizer composes the final grounded response. To close the trust loop, a word-level SequenceMatcher aligns each answer back to its source PDF with highlighted annotations, so users can see exactly where every claim originates.

Under the hood, the corpus — 280 pages and over 1,045,000 characters across the three regulatory PDFs — was chunked into 2,758 semantic segments using a 500-character window with 100-character overlap, balancing retrieval granularity against context coherence.

`Python` · `Qdrant` · `gemini-embedding-001` · `BM25` · Reciprocal Rank Fusion · LLM re-ranking · `FastMCP` · `DuckDuckGo` · Multi-agent orchestration

### Key Highlights

- Hybrid retrieval fusing Qdrant vector search and BM25 via Reciprocal Rank Fusion
- LLM listwise re-ranking (temperature 0) over 16 candidates, returning top-8 chunks
- Three-agent pipeline: Internal Researcher → External Fact-Checker → Synthesizer
- Word-level chunk-to-PDF alignment with highlighted source annotations

**3. End-to-End MLOps Pipeline: Taxi Fare Prediction**

### Overview

This project is a production-grade MLOps system that predicts NYC taxi fares while automating the entire machine learning lifecycle — from data ingestion to deployment to automated retraining. It's less about squeezing out the last decimal of model accuracy and more about the engineering that keeps a model reliable in production: enforced data contracts, full experiment tracking, containerized serving, and a self-updating retraining loop that keeps predictions accurate as live data drifts.

### What It Does

The system ingests NYC taxi trip data, trains and tracks fare-prediction models, and serves them behind a REST API — all orchestrated as an automated pipeline. Every stage is instrumented, validated, and reproducible, so the model in production is always traceable, monitored, and current rather than a stale, hand-deployed artifact.

### How It Works

Orchestration runs on **Airflow 3**, coordinating the pipeline from data ingestion through training, evaluation, and deployment. Experiments and model versions are tracked in **MLflow**, giving full visibility into how each model was produced and how it compares to its predecessors. The trained model is packaged with **FastAPI** and **Docker** for consistent, portable serving.

Data quality is treated as a first-class concern. **Great Expectations** enforces data contracts that validate incoming data before it ever reaches the model, catching schema and quality violations early and reducing silent failures. All validation and pipeline metrics are logged through a custom **PostgreSQL / SQLAlchemy** layer for durable, queryable observability.

The pipeline also retrains itself. A **Champion–Challenger** promotion strategy, driven by Airflow DAGs, periodically trains a challenger model, evaluates it against the reigning champion, and promotes it only if it wins — ensuring the production model stays accurate against live data without manual intervention.

### Tech Stack

`Python` · `Airflow 3` · `MLflow` · `FastAPI` · `Docker` · `Great Expectations` · `PostgreSQL` · `SQLAlchemy`

### Key Highlights

- Full ML lifecycle automation: ingestion → tracking → deployment
- Airflow 3 orchestration with MLflow experiment and model tracking
- Containerized serving via FastAPI and Docker
- Great Expectations data contracts to catch quality issues before inference
- Custom PostgreSQL/SQLAlchemy metrics logging for observability
- Automated Champion–Challenger retraining to counter data drift
